# Экраны

Экран — это то, что занимает всё окно выше ряда функциональных кнопок. Файловые
панели, просмотрщик текста, редактор, результаты поиска — всё это экраны, и ядро
не знает про них ничего, кроме контракта.

Ряд кнопок остаётся на месте **всегда**: он показывает команды того экрана,
который сейчас видно.

## Зачем понадобилось

Полноэкранного режима в приложении не было, а соседние точки расширения не
подходили:

* `PanelViewports` рисует содержимое **панели** — результаты поиска или дерево
  внутри панели, но не вместо неё;
* окно команды (`AppCommand.getDialog`) рисуется поверх всего, забирает клавиши
  целиком и живёт ровно один запуск команды.

Просмотрщику нужно третье: занять место панелей, оставить ряд кнопок и
переназначить его.

## Контракт

`fc_api`, [`src/app/screen.dart`](../dependency/api/lib/src/app/screen.dart):

```dart
abstract interface class Screen {
  String get id;            // устойчивое имя: к нему привязываются клавиши
  bool get takesFocus;      // нужен ли экрану фокус клавиатуры
  Widget build(BuildContext context);
}

abstract interface class Screens implements Listenable {
  static const String files = 'files';   // общеизвестное имя экрана панелей

  Screen? get active;       // виден верхний; null — показывать нечего
  void open(Screen screen); // поверх текущего; тот же id — замена, а не второй слой
  void close(String id);
}
```

`Application.screens` отдаёт службу, реализация — `ScreensController` в ядре
([`lib/state/screens_controller.dart`](../lib/state/screens_controller.dart)).

**Стопка, а не одно значение.** Просмотрщик открывается поверх панелей и,
закрываясь, возвращает их такими же, какими они были, — а не открывает заново.

## Кто рисует

`ApplicationView` показывает `screens.active` вместо панелей; `BackgroundBar` и
`FunctionBar` остаются под ним. Пусто — значит модуль панелей отключён:
приложение при этом работает, просто выше кнопок ничего нет. Так же честно, как
сейчас без корневого провайдера.

Экран панелей приносит модуль `fc_panels` и открывает его стартовой командой —
то есть до первого кадра.

## Клавиши принадлежат экрану

`KeyBinding.screen` говорит, в каком экране привязка действует. Умолчание —
`Screens.files`: сегодня почти все привязки панельные, и объявлять это в
тридцати местах незачем. `null` означает «в любом экране».

```dart
KeyBinding('F5', 'file.copy')                                   // в панелях
KeyBinding('F2', 'viewer.wrap', screen: ViewerScreen.screenId)  // в просмотрщике
```

`CommandRegistry.bindingFor` отбрасывает привязки чужих экранов, и из этого
**само собой** следует поведение ряда кнопок: он и раньше спрашивал у реестра,
что висит на `F1`…`F10`, — значит в просмотрщике он показывает команды
просмотрщика, а панельные клавиши там молчат. Ни ряд, ни разбор нажатий ради
этого не переписывались.

Отсюда же правило: **экран не рисует свой ряд кнопок с подписями от себя.**
Иначе кнопка и клавиша однажды разойдутся.

Экрана нет вовсе (приложение без интерфейса — тест состояния, сценарий,
будущая командная строка) — привязка действует: ограничивать нечем. Экран про
то, кому принадлежит клавиша, а не про то, можно ли выполнить команду.

## Фокус

`Screen.takesFocus` отвечает на вопрос, нужен ли экрану фокус клавиатуры.
Умолчания нет нарочно: от ответа зависит, дойдут ли до содержимого стрелки, и
молчаливое «нет» пришлось бы потом искать.

* **Панели** — нет. Какая из них активна, знает приложение, а нажатия разбирает
  общий обработчик.
* **Просмотрщик** — нет. Прокрутка у него сделана командами (`Up`, `PgDn`,
  `Home`…), как и всё остальное: клавиша принадлежит экрану, ряд кнопок
  показывает, что она сделает, и переназначить её можно будет из настроек.
* **Редактор** — да, иначе некуда печатать.

Пока такой экран открыт, `KeyboardHandler` пускает фокус внутрь
(`descendantsAreFocusable`), и нажатия, которые содержимое не взяло, всплывают
к общему разбору.

**Закрываясь, такой экран обязан вернуть фокус.** Он уносит с собой узел, у
которого фокус был, а объемлющая область истории не помнит: фокус достаётся ей
самой, то есть никому, — и приложение перестаёт слышать клавиатуру целиком.
Снаружи это выглядит как зависшее окно.

Возврат сделан в `KeyboardHandler` и **точечный**: обработчик ждёт фокус ровно
после ухода экрана, который его забирал, и берёт только осиротевший — признак
того, что фокусом никто не владеет, это `FocusScopeNode` в качестве текущего
фокуса, потому что у настоящего хозяина узел обычный. Забирать фокус в общем
случае нельзя: он уходит и по делу — в окно команды, в вопрос о пароле, в
соседнее приложение по `Cmd-Tab`.

## Экраны, которые есть

| Экран | Модуль | Фокус | Клавиши |
|---|---|---|---|
| `files` | `fc_panels` | нет | все панельные |
| `viewer` | `fc_viewer` | нет | `F2` перенос, `Esc`/`F10` выход, `Cmd-C` копировать, стрелки и страницы — прокрутка |

## Как добавить свой

1. Класс, реализующий `Screen`: устойчивый `id`, ответ про фокус, `build`.
2. Команда, которая его открывает: `context.app.screens.open(...)`.
3. Привязки с `screen: <id>` — на то, что экран умеет. Подпись команды видна в
   ряду кнопок, поэтому она должна говорить, что клавиша сделает **сейчас**
   (у переноса строк в просмотрщике подпись меняется: `Wrap` / `Unwrap`).
4. Оформление — общее: `FcPanelFrame` и `FcPathPlate` из `fc_ui_kit`. Место в
   окне у всех экранов одно, и выглядеть они обязаны одинаково.
