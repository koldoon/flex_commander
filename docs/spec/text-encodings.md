# Старые кодировки текста

**Состояние:** сделано 7 октября 2026 года, ветка `text-encodings`; ждёт
живой проверки. Отметки по ходу — в конце.

## 1. Зачем

Просмотрщик и редактор знают только UTF-8. Файл в Windows-1251 или KOI8-R
просмотрщик показывает знаками замены, редактор не открывает вовсе («Not a
UTF-8 text file»). Хуже того, служба типов считает такой файл **двоичным**: у
него значок двоичного, а `F3` открывает сведения, а не текст. Кириллица в
старых кодировках встречается до сих пор: логи, субтитры, исходники и
конфигурации из девяностых, файлы с Windows-машин.

## 2. Какие кодировки

| Имя в окне | Где встречается |
|---|---|
| UTF-8 | всё современное |
| UTF-16 LE, UTF-16 BE | Windows-блокнот «Unicode»; только с меткой порядка байтов |
| Windows-1251 | Windows, кириллица |
| KOI8-R | Unix, почта, старый интернет |
| KOI8-U | то же с украинскими буквами |
| CP866 | DOS, консоль Windows |
| Mac Cyrillic | старые Mac |
| ISO-8859-5 | редкая, но стандартная |
| Windows-1252 | западноевропейские языки — запасная для «не кириллицы» |

Однобайтовые таблицы — свои, в коде (`fc_text_kit`), выписаны из таблиц Python
(`codecs`) скриптом, а не руками. Зависимости ради таблиц на 256 знаков не
нужно.

**Неопределённые байты.** В части таблиц есть дыры (`0x98` в Windows-1251).
Строгое чтение на них отказывает, мягкое — ставит знак замены. Просмотрщик
читает мягко, редактор — строго (§5).

## 3. Определение при открытии

Порядок, первое сработавшее решает:

1. **Метка порядка байтов**: `EF BB BF` — UTF-8, `FF FE` — UTF-16 LE, `FE FF` —
   UTF-16 BE. Метка запоминается: сохранение пишет её обратно.
2. **Правильный UTF-8** — UTF-8. ASCII сюда же: он правильный UTF-8.
3. **Однобайтовые кандидаты** — кириллические по очереди. Каждый читается
   строго (с дырами кандидат выбывает) и получает **оценку**: сумму частот
   русских букв, где строчная буква весит полную частоту, прописная — десятую
   её часть, а псевдографика и прочие знаки из верхней половины таблицы
   штрафуются. Берётся кандидат с лучшей оценкой.

   Почему это работает: в правильной кодировке текст — это в основном строчные
   буквы частых звуков (о, е, а, и, н, т, с…). Неправильная кодировка
   переставляет буквы: KOI8-R, прочитанный как Windows-1251, даёт прописные
   редких букв вперемешку, а CP866 — псевдографику.
4. **Ни одной кириллической буквы** у лучшего кандидата — Windows-1252: это
   западный текст с акцентами.
5. Не прочёлся строго ни один — Windows-1252 мягко (просмотрщик) или отказ
   (редактор).

Определяется по **началу** файла (до 64 КБ): на больших файлах читать всё ради
выбора незачем, а статистика набирается быстро.

Определение — догадка. Ошибётся — человек выбирает сам (§4).

## 4. `F8` — выбрать руками

В просмотрщике и в редакторе `F8` открывает окно **«Encoding»** со списком
§2. Курсор стоит на нынешней.

* **Выбранное видно сразу**: стрелки по списку перечитывают текст под окном,
  `Enter` или «OK» оставляет, `Esc` или «Cancel» возвращает прежнее. Это то же
  окно, что у соотношения сторон видео (`video-viewer.md`, §6б), — оно
  выносится в `fc_ui_kit` общим (§8).
* Перечитываются **байты файла**, а не показанный текст: показанный уже
  испорчен неверной кодировкой.
* **В редакторе с несохранёнными правками** `F8` отказывает тостом: «Save or
  discard the changes before changing the encoding». Перечитать байты значило
  бы выбросить правки, а перекодировать набранное — гадать, что человек имел в
  виду.
* Где стоит показ: на плашке пути справа — имя кодировки, если это **не**
  UTF-8. UTF-8 не пишется: он подразумевается, и подпись на каждом файле была
  бы шумом.
* В быстром просмотре выбранная руками кодировка помнится, пока он открыт —
  памятью показа (`quick-view.md`, §3.2), как соотношение сторон у видео.
  Между показами не помнится: следующий файл определяется заново.

## 5. Редактор

* **Открывает** файл в определённой кодировке. Отказ «Not a text file» — только
  когда строго не прочёлся ни один кандидат, то есть правка испортила бы байты.
  Старая строка «Not a UTF-8 text file» уходит.
* **Сохранение файла не в UTF** (то есть не UTF-8 и не UTF-16) — окно
  подтверждения сохранения и окно «несохранённых правок» при закрытии получают
  поле **«Encoding»** (`FcSelect`): исходная кодировка файла или UTF-8. По
  умолчанию — исходная. Это и есть вопрос «в чём сохранять», без третьего окна
  между ними.
* Выбрано **UTF-8** — файл записывается в UTF-8 без метки, и дальше редактор
  считает его UTF-8: следующее сохранение больше не спрашивает.
* Выбрана **исходная** — перед записью проверяется, всё ли помещается. Не
  помещается — запись не идёт, окно остаётся открытым, тост называет первый
  знак и строку: «“€” on line 12 does not fit in KOI8-R». Человек правит текст
  или выбирает UTF-8 в том же окне.
* UTF-16 и UTF-8 с меткой сохраняются как были, без вопроса.
* Кодирует **ядро**, там же, где пишет (`EditorSaving`): экран присылает текст и
  имя кодировки с признаком метки. Проверка «всё ли помещается» — на экране, до
  заявки, чтобы ответ пришёл в окно сразу; ядро на всякий случай проверяет
  тоже и отказывает `FsError`.
* Перевод строки помнится, как и раньше, — отдельно от кодировки.

## 6. Служба типов

Текст в однобайтовой кодировке перестаёт быть двоичным (`text_probe.dart`):
неправильный UTF-8 без нулевых байтов и почти без управляющих знаков —
текст. «Почти» — не больше 1% байтов из `01–08`, `0E–1A`, `1C–1F`, `7F`
(табуляция, переводы строк, `FF` страницы и `ESC` законны). Двоичное почти
всегда содержит нули уже в первых сотнях байтов, а управляющих в нём много.

Сам вопрос «какая это кодировка» служба типов не решает: ей хватает ответа
«текст».

## 7. Markdown

Просмотрщик markdown определяет кодировку тем же правилом (§3), без `F8`:
markdown почти всегда UTF-8, а выбор руками — забота просмотрщика текста
(`F5` уводит в исходник, там и `F8`).

## 8. Общее окно выбора

Окно выбора из списка с показом выбранного сразу появляется второй раз
(соотношение сторон, кодировка) — выносится в `fc_ui_kit` как
`showChoiceDialog`: заголовок, строки, нынешняя, «показать вот это», «оставить»
и «вернуть». Окно соотношений сторон переводится на него в том же шаге.

## 9. Где живёт

* `dependency/text_kit/lib/src/text_encoding.dart` — `TextEncoding`, таблицы,
  определение, чтение и запись. Чистый Dart: им пользуется и ядро.
* `dependency/text_kit/tool/encoding_tables.py` — откуда таблицы.
* `dependency/content_types/lib/src/text_probe.dart` — §6.
* `dependency/ui_kit/lib/src/choice_dialog.dart` — §8.
* просмотрщик (`text_viewer`), редактор (`editor`), markdown — §4, §5, §7.

## 10. Проверка

* Таблицы: каждая однобайтовая кодировка — круг «байты → текст → байты» на
  всех определённых байтах; известные слова в известных байтах.
* Определение: «Привет, мир» и абзац русского текста в каждой кириллической
  кодировке узнаются; UTF-8 с меткой и без; UTF-16 с меткой; французский в
  Windows-1252; ASCII — UTF-8.
* Служба типов: текст в Windows-1251 — текст; настоящее двоичное — двоичное.
* Просмотрщик: файл в KOI8-R показан по-русски, плашка говорит «KOI8-R»;
  `F8` → Windows-1251 перечитывает; `Esc` возвращает; быстрый просмотр помнит.
* Редактор: открывает Windows-1251; `F8` с правками отказывает; сохранение
  с выбором исходной пишет Windows-1251; с выбором UTF-8 — UTF-8, и второй раз
  не спрашивает; «€» в KOI8-R — отказ тостом, файл не тронут.
* **Живьём — пользователь**: файлы с Windows-машины и старые логи.

## 11. Отметки по ходу

* **Шаг 1** — `TextEncoding` и `EncodedText` в `fc_text_kit`, таблицы из Python.
* **Шаг 2** — служба типов: однобайтовый текст не двоичный.
* **Шаг 3** — `showChoiceDialog` в `fc_ui_kit`; соотношение сторон видео на нём.
* **Шаг 4** — просмотрщик текста и markdown.
* **Шаг 5** — редактор: открытие, поле «Encoding» в обоих окнах сохранения,
  `F8`, кодирование в ядре.
* **Однобайтовая таблица прочтёт и двоичное.** Первый тест редактора на
  `C3 28 FF 00` открыл бы двоичный файл как Windows-1251: в определение
  добавлено правило службы типов (нули, управляющие знаки) — `detect` для
  такого отвечает null. Без этого редактор пустил бы двоичное на правку.
* `CommandDialogConfirm` получил `fields` — поля под вопросом; так окно
  сохранения спрашивает кодировку, не заводя третьего окна.
