# Ход внутри файла на локальной ФС — от `copyfile(3)`

**Состояние:** спецификация от 21.08.2026, код написан и проверен тестами;
остаётся проверка на живом. Отметки о ходе работы —
§7; готовый контракт по итогам уедет в [`models.md`](../models.md) и
[`providers.md`](../providers.md), а этот файл останется записью о том, что
решалось и почему.

Копирование файла из папки в папку на локальном диске показывает полосу `File`
на нуле до самого конца, а распаковка того же файла из ZIP — показывает честно.
Здесь описано, почему так вышло и чем это лечится.

## 1. Что не так сейчас

Движок переноса выбирает стратегию по паре «источник — приёмник»
(`api/…/transfer/transfer_engine.dart`, `_copyTree`). Для двух узлов одного и
того же провайдера берётся `providerCopy` — копирует сам провайдер:

```dart
progress.startItem(node.name, bytes: node.size < 0 ? null : node.size);

if (source != null && identical(source, target) && await source.copyEntry(node, destination, name)) {
  // Байты прошли мимо движка — он видит только, что файл целиком скопирован.
  progress.advanceBytes(node.size);
  return;
}
```

`startItem` выставил `itemBytes = 0`, а `advanceBytes` зовётся **один раз, после
готовой копии**. Между этими двумя строками может пройти пять минут, и всё это
время окно показывает `0 B of 4.0 GB` и пустую полосу.

У локальной ФС `copyEntry` — это `File.copy` (`local_tree_provider.dart`), то
есть один системный вызов, который отдаёт управление только целиком
скопированным файлом. Ничего другого движку взять неоткуда.

ZIP работает потому, что там **разные провайдеры**: `identical` не срабатывает,
`providerCopy` пропускается, и идёт стратегия `stream` — `openRead → openWrite`,
где `progress.advanceBytes(chunk.length)` зовётся на каждом куске. Разница не в
архиве и не в размере файла, а ровно в том, один ли провайдер с обеих сторон.

Тем же местом объясняются ещё две вещи, о которых стоит сказать сразу:

* **Общая полоса тоже стоит.** Доля считается по байтам, когда объём известен, —
  а байт нет до самого конца. Работа из одного большого файла выглядит замершей
  целиком, а не только строкой `File`.
* **`Esc` не прерывает ничего.** `op.checkpoint()` стоит **между** объектами;
  внутри `File.copy` его нет и быть не может. Локальная копия на четыре
  гигабайта сегодня непрерываема — окно закроется, а диск ещё пять минут будет
  занят работой, которую отменили.

Сегодняшнее поведение записано в [`models.md`](../models.md) как намеренное:
«Там, где байты идут мимо него (провайдер копирует файл сам, переименование
переносит поддерево разом), объём засчитывается целиком по размеру объекта».
Для переименования это по-прежнему верно, для локальной копии — больше нет:
эта работа меняет и доктрину, а не только код.

## 2. Что получается

Окно копирования на большом файле:

```
┌ Copy ────────────────────────────────────────────┐
│   Item    Copying archive.dmg…                   │
│   File    archive.dmg                            │
│           1.4 GB of 4.0 GB                       │
│           ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░   │
│  Speed    212.4 MB/s, 12s left                   │
│  Total    1 of 1                                 │
│           1.4 GB of 4.0 GB                       │
│           ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░   │
├──────────────────────────────────────────────────┤
│                      [Background]  [Cancel]      │
└──────────────────────────────────────────────────┘
```

Ничего нового в окне не появляется — все строки уже есть
(`ui_kit/…/command_dialog.dart`), им просто нечем было двигаться. Скорость и
оценка времени начинают работать сами собой: `_SpeedWindow` считает по
`advanceBytes`, а его до сих пор звали раз на файл.

`Esc` посреди большого файла:

* окно спрашивает `Abort the operation?` — тот же вопрос, что и всегда;
* **копия при этом не останавливается**, полоса продолжает идти;
* `Resume` — ничего не произошло, время не потеряно;
* `Abort` — копия бросается на ближайшем куске, недописанный файл убирается.

## 3. Контракт

### 3.1. Примитив отдаёт свои байты

`NodeEditor.copyEntry` (`api/…/tree/tree_provider.dart`) получает необязательный
колбэк:

```dart
/// Копия одного объекта средствами провайдера.
///
/// [onBytes] — сколько байт легло в приёмник с прошлого раза. Молчать можно
/// всегда: движок засчитает объём целиком, когда копия готова, — но тогда
/// большой файл так и останется «нулём до конца».
///
/// false из [onBytes] — копию пора бросить. Не мгновенно: провайдер прекращает
/// работу на ближайшем куске и бросает [OperationCanceled], а убирает
/// недописанное движок.
Future<bool> copyEntry(
  FsNode node,
  DirectoryNode destination,
  String name, {
  bool Function(int bytes)? onBytes,
});
```

Колбэк, а не `AsyncOperation`: примитив остаётся примитивом — без отмены, без
прогресса, без вопросов, — и отчитывается ровно так же, как уже отчитывается
`TreeProvider.countEntries(node, onEntry)`. Второго способа рассказать о себе в
интерфейсе провайдера не заводится.

Реализаций пять: локальная ФС (§3.4), `InMemoryTreeProvider` в `test_kit`
(отдаёт байты кусками — на нём проверяется движок) и три, которые и сегодня
отвечают `false`, а колбэк игнорируют: `writable_zip`, `writable_seven_zip`,
`sftp`.

### 3.2. Вопрос, который не останавливает работу

`TaskOperation` (`api/…/async/async_operation.dart`) получает несинхронный
вариант `checkpoint()`:

```dart
/// Отмена для работы, которую нельзя ни приостановить, ни возобновить.
///
/// Возвращает false, когда работу пора бросить. Просьбу прервать превращает в
/// тот же вопрос, что и [checkpoint], но ответа **не ждёт**: остановить
/// `copyfile` на середине нельзя, а стоять на месте, пока файл всё равно
/// копируется, — обман. Пока пользователь думает, работа идёт и полоса
/// движется; ответ «прервать» доходит до неё следующим куском.
bool keepRunning();
```

Внутри — то же, что и в `checkpoint`, но без `await` у зовущего:

* `isCanceled` → `false`, работу пора бросить;
* просьба есть, а вопрос ещё не задан → `unawaited(checkpoint())` с защёлкой
  (иначе вопрос задавался бы на каждом куске) и с проглоченным
  `OperationCanceled`: об отмене зовущий узнаёт из следующего `false`, а не из
  броска в чужом такте;
* иначе → `true`.

### 3.3. Движок

`_copyTree`, ветка `providerCopy`:

```dart
var reported = 0;
bool onBytes(int bytes) {
  reported += bytes;
  progress.advanceBytes(bytes);
  return op.keepRunning();
}

if (source != null && identical(source, target)) {
  final bool copied;
  try {
    copied = await source.copyEntry(node, destination, name, onBytes: onBytes);
  } on FsError {
    await _discardPartial(target, destination, name);
    rethrow;
  } on OperationCanceled {
    await _discardPartial(target, destination, name);
    rethrow;
  }
  if (copied) {
    // Провайдер мог промолчать: тогда объём засчитывается целиком, как раньше.
    progress.advanceBytes(node.size - reported);
    return;
  }
}
```

Два следствия, оба нужные:

* **уборка недописанного распространяется на `providerCopy`.** Сегодня
  `_discardPartial` есть только у стратегии `stream`, и оборванная копия
  провайдера оставляет половину файла под настоящим именем — «половина файла
  под настоящим именем выглядит как целый файл»;
* **добор `node.size - reported`** держит старое поведение для всех, кто
  колбэк не поддерживает: разница уходит в `advanceBytes`, а тот сам
  отбрасывает ноль и отрицательное (размер неизвестен — `node.size` равен `-1`).

### 3.4. Локальная ФС: `copyfile(3)` через FFI

Новый файл `lib/modules/local_fs/local_file_copy.dart`:

```dart
/// Копия файла средствами macOS `copyfile(3)` — с ходом по байтам и отменой.
///
/// [onBytes] зовётся в текущем изоляте приростом байт; false из него бросает
/// копию (`COPYFILE_QUIT`) на ближайшем куске и даёт [OperationCanceled].
/// Ошибка `copyfile` приходит [FsError] по `errno`.
Future<void> copyFileWithProgress(String source, String target, bool Function(int bytes) onBytes);
```

Как устроено:

* **символы** берутся у `DynamicLibrary.process()` — libSystem уже загружена, и
  ничего доустанавливать не нужно: `copyfile`, `copyfile_state_alloc`,
  `copyfile_state_free`, `copyfile_state_set`, `copyfile_state_get`;
* **константы** (`COPYFILE_ALL`, `COPYFILE_STATE_STATUS_CB`,
  `COPYFILE_STATE_COPIED`, `COPYFILE_COPY_DATA`, `COPYFILE_PROGRESS`,
  `COPYFILE_CONTINUE`, `COPYFILE_QUIT`) переписываются из `/usr/include/copyfile.h`
  при реализации и **проверяются тестом**: сверить их больше не с чем, а ошибка
  здесь роняет процесс, а не бросает исключение;
* **вызов идёт в `Isolate.run`**: `copyfile` синхронный, и на четырёх
  гигабайтах он заморозил бы интерфейс. Тот же приём уже применён к чтению
  каталога (`local_listing.dart`);
* **колбэк** — `NativeCallable.isolateLocal`. Он годится именно потому, что
  `copyfile` зовёт колбэк на том же потоке, который его вызвал, то есть на
  потоке изолята; `listener` с его асинхронностью здесь не нужен;
* **байты наружу** уходят `SendPort`'ом, с прореживанием: не чаще, чем раз в
  50 мс, и не мельче полумегабайта. Окно всё равно перерисовывается по
  `Throttle` (50 мс), а `copyfile` зовёт колбэк на каждый блок;
* **отмена внутрь** — `Int32` в нативной памяти (`calloc`); адрес передаётся в
  изолят обычным числом, а `Pointer.fromAddress` собирает его обратно. Порт для
  этого не годится: изолят стоит в нативном вызове и сообщений не читает.
  Колбэк читает флаг сам и возвращает `COPYFILE_QUIT`;
* **`errno`** читается сразу после неудачи (`__error()`) и переводится в
  `FsError` существующим `fsErrorFrom`; `ECANCELED` после `QUIT` — это
  `OperationCanceled`, а не ошибка;
* **уборка** — `copyfile_state_free`, `NativeCallable.close()` и `calloc.free`
  в `finally`, при любом исходе.

`LocalTreeProvider.copyEntry` выбирает путь:

```dart
if (onBytes == null || node.size < settings.copyProgressMinBytes) {
  await File(source).copy(target);          // как сегодня: без изолята и колбэка
} else {
  await copyFileWithProgress(source, target, onBytes);
}
```

Флаги — **`COPYFILE_ALL`, без `COPYFILE_CLONE`** (см. §4). Ссылки и каталоги
идут по сегодняшним веткам `copyEntry` и FFI не касаются.

### 3.5. Настройка

Новый `lib/modules/local_fs/local_fs_settings.dart`, раздел `fc.local_fs` —
по образцу `SevenZipSettings`:

```dart
/// Что модуль локальной ФС помнит между запусками.
class LocalFsSettings implements Serializable {
  LocalFsSettings({this.copyProgressMinBytes = 1 << 20});

  /// С какого размера файл копируется с показом хода внутри него.
  ///
  /// Ход внутри файла стоит изолята и нативного колбэка на каждый файл: на
  /// дереве из десятков тысяч мелких файлов это дороже самой копии. Ниже порога
  /// файл копируется одним действием, а объём засчитывается по концу — как
  /// было всегда. 0 — показывать ход у любого файла.
  int copyProgressMinBytes;
}
```

Раздел читается **лениво, на каждой копии**, а не подставляется в конструктор
провайдера: `LocalTreeProvider` создаётся раньше, чем прочитаны настройки, —
`SettingsStore.forHome` берёт `homePath` у него самого
(`bootstrap/app_container.dart`). Поэтому модуль отдаёт провайдеру не значение,
а способ его узнать:

```dart
// LocalFileSystem.install
final settings = registry.settings;
registry.rootProvider((services) => LocalTreeProvider(settings: () => settings.section(LocalFsSettings.new)));
```

В тестах провайдер создаётся без этого замыкания и берёт умолчание.

## 4. Решения

* **FFI, а не опрос размера приёмника.** Смотреть, как растёт целевой файл, —
  дешевле на день работы, но это эвристика: при клонировании и
  предварительном выделении места рост не виден, и полоса врёт. Главное же —
  опрос не даёт **отмены внутри файла**, а она здесь такая же часть работы, как
  и полоса: сегодня локальная копия на четыре гигабайта не прерывается вовсе.
* **FFI, а не поток `openRead → openWrite` для больших файлов.** Поток дал бы
  ровный ход тремя строками, но локальная копия перестала бы сохранять то, что
  сохраняет `copyfile`: дату, права, xattr, ACL. `capabilities.preservesModified`
  у локальной ФС объявлен `true`, и врать об этом ради полосы нельзя.
* **`COPYFILE_ALL` без `COPYFILE_CLONE`.** Клон на APFS сделал бы копию в
  пределах тома мгновенной, но `COPYFILE_CLONE` подразумевает `COPYFILE_EXCL`
  (целевого пути не должно быть) и, что важнее, при клоне колбэк данных не
  приходит **ни разу** — то есть ровно та работа, ради которой всё затевается,
  на самом частом случае и пропала бы. Клон — отдельное решение с отдельной
  ценой (§8), и принимать его заодно нельзя.
* **Вопрос об отмене не останавливает копию.** Приостановить `copyfile`
  невозможно — только бросить. Значит выбор был из трёх: ждать конца файла
  (сегодняшнее — минуты), бросать молча (`Esc` становится необратимым внутри
  файла — ровно тот случай, ради которого вопрос и заводился) или спрашивать
  поверх идущей работы. Третье и выбрано: пользователь всё это время видит
  движущуюся полосу, а «Resume» не стоит ему ничего.
* **Порог — настройка, а не константа.** Полезное значение зависит от диска:
  на медленной флешке заметен и мегабайт, на NVMe не заметны и сто. Умолчание
  1 МиБ — ниже него файл копируется быстрее, чем окно успевает перерисоваться.
* **Отчитывается провайдер, решает движок.** Провайдер отдаёт свои байты и
  спрашивает «продолжать?»; сколько всего работы, кто следующий и что делать с
  недописанным файлом — по-прежнему знает только движок. Разделение то же, что
  и было, добавился один канал в уже существующем направлении.
* **Запасной путь остаётся.** `File.copy` никуда не девается: он же работает
  ниже порога, он же — на всём, что не macOS, и он же, если символы `copyfile`
  почему-то не нашлись. Двух расходящихся поведений это не создаёт: результат
  один и тот же, разница только в том, рассказывают ли о ходе.

## 6. Проверка

Тесты:

* `test/model/transfer_test.dart` (настоящая ФС во временном каталоге): файл
  выше порога даёт **промежуточные** сообщения — есть отчёт, где `itemBytes`
  больше нуля и меньше размера; сумма байт по концу равна размеру; файл ниже
  порога проходит без колбэка.
* `test/model/local_file_copy_test.dart` (новый): FFI напрямую — копия побайтово
  равна источнику; дата и права сохранены; байты растут и в сумме дают размер;
  `false` из колбэка бросает копию, даёт `OperationCanceled` и не оставляет
  файла; несуществующий источник даёт `FsError`, а не падение процесса.
* `test/model/transfer_engine_test.dart` (`InMemoryTreeProvider`): провайдер,
  отдающий байты кусками, двигает и общий счёт; провайдер, который молчит,
  по-прежнему засчитывается целиком; отмена посреди файла убирает недописанное.
* `dependency/api/test/async/`: `keepRunning()` — до просьбы возвращает `true`
  и вопросов не задаёт; после просьбы задаёт **один** вопрос и продолжает
  возвращать `true`, пока нет ответа; после «Abort» возвращает `false`.

На живом (проверяет пользователь):

* многогигабайтный файл на внешний диск: полоса `File` движется, скорость и
  оценка времени правдоподобны, общая полоса идёт вместе с ней;
* каталог из тысяч мелких файлов: копирование не стало медленнее (порог держит
  их на старом пути);
* `Esc` посреди большого файла: вопрос появился, полоса **продолжает идти**;
  `Resume` — работа как ни в чём не бывало; `Abort` — работа прекратилась за
  секунду, недописанного файла в приёмнике нет.

## 8. Что остаётся за рамками

* **Клон APFS** (`COPYFILE_CLONE`). Мгновенная копия в пределах тома — заметная
  вещь, но у неё своя цена: `COPYFILE_EXCL` в подарок и полное отсутствие хода
  по байтам. Стоит решать отдельно и, скорее всего, тоже настройкой.
* **Другие платформы.** `copyfile(3)` — macOS. Windows дал бы то же самое через
  `CopyFileEx` с `LPPROGRESS_ROUTINE`, Linux — своим циклом; пока приложение
  собирается только под macOS, там остаётся `File.copy`.
* **Отмена внутри файла у сетевых источников.** Стратегия `stream` уже
  прерывается между кусками; серверный `COPY` (когда он появится у sftp) — это
  тот же `providerCopy`, и `onBytes` для него уже будет.
* **Параллельные копии.** `capabilities.maxConcurrency` у локальной ФС равен 16,
  но движок копирует по одному объекту. Своя работа со своим окном.
