# Корзины S3

**Состояние:** в работе. Отметки по ходу — в §17.

Этап [Ж13](../roadmap.md#ж13-корзины-s3-minio-google-storage-и-прочие-совместимые).
Адрес `s3://…` — и панель стоит на хранилище: корзины списком, внутри префиксы
каталогами и объекты файлами. `F3`, `F4`, копирование в обе стороны,
удаление, создание каталога, переименование. Один клиент — много хранилищ:
AWS S3, MinIO, Google Cloud Storage (режим совместимости с HMAC-ключами), R2,
Backblaze, Yandex.

## 1. Чего сейчас нет

Хранилище объектов — то место, куда сегодня кладут резервные копии, сборки,
выгрузки и раздаваемые файлы. Достать оттуда файл сейчас можно только чужой
программой: `aws s3 cp`, `mc`, веб-консоль. В файловом менеджере, который
умеет `ssh`, `ftp` и архивы, это заметная дыра.

## 2. Что получается

* `s3+http://fctest@192.168.42.2:9000/fc-test` — панель в корзине MinIO;
* `s3://AKIA…@s3.amazonaws.com/my-bucket/backups` — в префиксе корзины AWS;
* `s3://GOOG…@storage.googleapis.com/` — список корзин Google Storage.

Секретный ключ спрашивает окно пароля — то же, что у архивов и серверов.
Сохранить соединение — значит положить адрес в избранное, как любой другой.

## 3. Разведка живого MinIO

*Заполняется до кода подписи и загрузки — по тому же правилу, по которому FTP
писался против живого сервера (`ftp.md`, §3).* Стенд — MinIO в контейнере
`fc-minio` на `192.168.42.2:9000` (образ `firstfinger/minio:latest-amd64`:
официальной раздачи готового MinIO больше нет — образа на Docker Hub нет,
`quay.io` отказывает, `dl.min.io` отвечает `410 Gone`). Запросы — `curl
--aws-sigv4`: подпись чужая, независимая от нашей, и ошибки в собственной
подписи не могут подтвердить ошибочную гипотезу.

Что ответил сервер (5 октября 2026):

| Вопрос | Ответ | Что из этого следует |
|---|---|---|
| тело без хеша (`UNSIGNED-PAYLOAD`) по **простому HTTP** | `200` | хешировать восьмимегабайтные части на Dart не нужно вовсе |
| неверный хеш тела | `400 XAmzContentSHA256Mismatch` | хеш, если дан, проверяется — и XML пачек подписываем настоящим |
| подпись чужим регионом (`eu-west-1`) | `200` | MinIO без своего региона его не проверяет: исправление региона на стенде не проверить, только на AWS |
| неверный секрет | `403 SignatureDoesNotMatch` | ключ отвергнут — забыть и спросить снова |
| неизвестный ключ | `403 InvalidAccessKeyId` | то же |
| ключи с пробелом, `+`, `%`, кириллицей, `?`, `:`, `~` | `200` все | кодирование пути по правилу 1 верно |
| листинг с `encoding-type=url` | пробел — `+`, плюс — `%2B`, тильда — `%7E`, кириллица — `%XX`; `<EncodingType>url</EncodingType>` в ответе есть | раскодировать **как форму** и только при этом признаке |
| маркер `dir/` в листинге родителя | только в `<CommonPrefixes>`, не ключом | маркер не двоится с префиксом |
| маркер `dir/` в листинге самого `dir/` | ключом в `<Contents>` | свою строку прятать |
| верхний `<Prefix>` ответа | запрошенный префикс | префиксы уровня — **только** из `<CommonPrefixes>`, иначе каталог покажет сам себя |

## 4. Устройство

Слои — те же, что у FTP (`ftp.md`, §4):

* `S3FileSystem` — модуль ядра, объявляет схемы `s3` и `s3+http`;
* `S3TreeProvider` — источник: пути, каталоги, умения; о протоколе не знает;
* `S3Api` — узкая граница с подставкой в тестах; наружу выходят только
  `FsError`;
* `S3Client` над `S3Http` — запросы, подпись, повторы, регион;
* `SigV4Signer` и правила кодирования — чистые функции, проверяемые векторами.

Клиент свой, на `dart:io` (`HttpClient`): готовые пакеты держат объект в памяти
целиком или не умеют читать потоком.

## 5. Адрес

`s3[+http]://[КЛЮЧ@]хост[:порт][/корзина[/префикс]][?region=…&style=…]`

* **Соединение — в адресе, как у `ssh` и `ftp`.** Записей соединений в
  настройках нет: их нет ни у одного сервера, и заводить окно ради одного
  источника — дорого. Сохраняют адрес избранное и история адресов.
* **Ключ доступа — на месте имени пользователя**, регистр сохраняется. Без него
  окно спросит оба поля.
* **`s3` — HTTPS, `s3+http` — простой HTTP**, как `ftp` и `ftps`: транспорт
  выбирает человек и видит его в адресе. Флаг в запросе потерялся бы, стоит
  отрезать хвост адреса.
* **Регион узнаётся сам**: по хосту AWS, иначе `us-east-1`; ошибся — ответ
  сервера называет правильный, запрос повторяется один раз. `?region=` —
  перекрыть.
* **Стиль адресации** — по хосту: AWS — поддомен корзины (кроме корзин с точкой
  в имени по TLS — сертификат не сойдётся), всё прочее — путь. `?style=` —
  перекрыть.
* **Секрета в пути нет никогда** — ни в строке панели, ни в истории, ни в
  ключе соединения (`ftp.md`, §11).

## 6. Ключи

Realm — `s3:КЛЮЧ@хост:порт` (с `s3+http` — своя схема). Одно поле («Secret
access key»), если ключ в адресе, два — если нет. Отвергнутый ключ
(`SignatureDoesNotMatch`, `InvalidAccessKeyId`) забывается и спрашивается
снова; `AccessDenied` на списке корзин — ключ верен, но прав на весь счёт нет,
и показывается корзина из адреса.

## 7. Подпись

SigV4 — чистой функцией с часами снаружи (`SigV4Signer`): канонический запрос,
строка для подписи, ключ подписи цепочкой из четырёх HMAC — один на сутки и
регион. Проверяется **опубликованными** числами AWS: четыре примера из
руководства S3 и вывод ключа из руководства IAM. Совпасть с ними случайно
нельзя.

**Хеш тела:** без тела — хеш пустого; XML (итог загрузки, пачка удалений) —
настоящий; содержимое файлов — `UNSIGNED-PAYLOAD`. По HTTPS целостность держит
TLS; по простому HTTP MinIO это принимает (§3), а хешировать восемь мегабайт
на Dart на каждую часть значило бы упереться в процессор.

## 8. Регион и часы

Регион до первого ответа — из адреса или хоста, иначе `us-east-1`. Ответ
назвал другой (`x-amz-bucket-region` или `<Region>` в ошибке) — запомнить для
корзины и повторить **один раз**. `RequestTimeTooSkewed` — взять время из
заголовка `Date` и тоже повторить один раз.

## 9. Путь, каталоги и маркеры

`/` — корзины; `/b` — корзина; `/b/a/c` — префикс `a/c/` или объект `a/c`.
Каталог — это префикс: пустых каталогов в S3 нет, кроме маркеров — объектов
нулевой длины с `/` на конце, которые заводят веб-консоли и мы сами (§12).

* в листинге родителя маркер приходит префиксом — и показывается каталогом;
* в листинге самого каталога маркер — ключ, равный префиксу, — не строка;
* `resolvePath` — за один оборот: последний сегмент проверяется параллельно и
  листингом `k/` (каталог), и `HEAD` (объект). Каталог побеждает;
* листинг — страницами по тысяче, с отменой между страницами и ходом работы в
  строке состояния.

## 10. Пять правил кодирования

1. **Путь запроса** — посегментно, UTF-8, всё кроме «unreserved» — `%XX`, `/`
   между сегментами остаётся. Тот же текст — в провод и в подпись: S3 не
   нормализует путь.
2. **Строка запроса** — то же, но и `/` кодируется; пары по закодированному
   ключу.
3. **`x-amz-copy-source`** — `/корзина/ключ` по правилу 1.
4. **Листинг с `encoding-type=url`** — раскодировать как форму (`+` — пробел),
   и только если ответ это сказал.
5. **Имена в панели** — сырые, никогда не закодированные.

Ключи с сегментами `.` и `..` не отправляются вовсе: `Uri` в Dart выбросил бы
их из пути, и запрос ушёл бы к чужому объекту.

## 11. Загрузка и отмена

`S3UploadSink`:

* известный размер до части — **один PUT** на закрытие;
* иначе **многочастно**: часть от 8 МиБ (растёт, чтобы частей было не больше
  десяти тысяч), до четырёх частей разом, источник на это время на паузе —
  памяти не больше пяти частей;
* `close()` — собрать объект (`Complete`); не вышло — отменить загрузку;
* `abort()` — оборвать запросы в полёте и `AbortMultipartUpload`.

**Отмена обязана убирать части на сервере.** Брошенные куски не видны в
листинге и лежат, пока их не уберут, — и считаются в счёт каждый месяц. Для
этого движку переноса понадобилось различать «готово» и «брось»: приёмник,
которому есть разница, говорит о себе интерфейсом `AbortableSink`, и после
ошибки или отмены движок зовёт `abort()` (`abandonSink`), а не `close()`.
Прочие приёмники этого не замечают — для них это прежний `close()`. Так же
бросают приёмник запись архива обратно (`WriteBack`) и упаковка в `tar` и `7z`.

## 12. Копия, переименование, удаление

* **Копия внутри хранилища — средствами сервера** (`CopyObject`); больше 5 ГиБ
  — многочастной копией частями по 512 МиБ. Байты через нас не идут.
* **Переименование объекта** — копия и удаление. `canRename` при этом **да**:
  «нет» погасило бы команду переименования и запись архива обратно. Префикс так
  не переименовать — это столько копий, сколько под ним ключей; `renameEntry`
  отвечает «нет» без единого запроса, и перенос каталога идёт копией дерева.
* **Каталог** — маркер `имя/` нулевой длины; копия дерева заводит их по одному
  на каталог, и пустые каталоги переживают копию. В корне каталог — корзина.
* **Удаление поддерева** — листинг без разделителя и `DeleteObjects` пачками по
  тысяче; хранилище без пачек (Google Storage) — поштучно. Удаление по `F8`
  идёт обходом движка, по объекту — ради честного хода работы.

## 13. Умения источника

| Умение | Значение | Почему |
|---|---|---|
| `canRename` | да | §12 |
| `canSeek` | да | `Range`: `zip` поверх S3 читается кусками даром |
| `preservesModified` | нет | дату объекта ставит хранилище |
| `realFileSystem` | нет | путь вне приложения ничего не значит |
| `maxConcurrency` | 8 | HTTP держит много запросов; крупный файл идёт один и грузится частями внутри приёмника |

## 14. Ошибки

| Ответ | `FsErrorKind` |
|---|---|
| не достучались (сокет, TLS, тайм-аут) | `cannotConnect` |
| `NoSuchKey`, `NoSuchBucket`, `NoSuchUpload`, 404 | `notFound` |
| `AccessDenied`, `SignatureDoesNotMatch`, `InvalidAccessKeyId`, 403 | `permissionDenied` (два последних — ключ отвергнут) |
| `BucketAlreadyExists`, `BucketAlreadyOwnedByYou` | `alreadyExists` |
| `InvalidBucketName`, `KeyTooLongError`, `XMinioInvalidObjectName` | `invalidName` |
| `NotImplemented`, 501 | `notSupported` |
| прочее | `io` |

Повторяются с нарастающей паузой перегрузка (`SlowDown`, 5xx) и обрыв сокета —
до четырёх раз. Итог многочастной загрузки и копия бывают ответом `200` с
`<Error>` внутри — тело читается всегда.

## 15. Чего в первой версии нет

* **Докачки** — её нет в движке ни для одного источника; отдельный этап.
* Версий объектов, классов хранения, ACL и политик, ссылок с подписью,
  шифрования своим ключом, `S3 Select`.
* HTTPS с самоподписанным сертификатом — как у FTP, отказ.
* Переименования префикса одним действием и удаления по `F8` пачками.
* Ключей с `:` в имени — `:` разделяет звенья пути приложения (как у FTP).

## 16. Проверка

* **Подпись** — векторами AWS; **кодирование**, **XML** — на образцах разведки;
  **адрес**.
* **Источник на подставке** (`FakeS3`): пути, листинг страницами и маркеры,
  каталог, копия, переименование, удаление пачками и поштучно, ключи и повтор,
  приёмник — PUT, части, предел частей в полёте и пауза источника, отмена без
  следов.
* **Движок** (`abortable_sink_test.dart`): успех — `close`, ошибка — `abort`,
  обычный приёмник — как прежде.
* **Живьём** (`real_s3_test.dart`, `FC_S3_TEST_HOST` и `FC_S3_TEST_SECRET`):
  вход, маленький и крупный файл с проверкой хеша, отмена многочастной загрузки
  без следов, трудные имена, копия и переименование, страницы листинга,
  неверный секрет. Стенд — MinIO на `shark`.
* В приложении — пользователь.

## 17. Отметки по ходу

**5 октября 2026.** Решено с пользователем поверх дорожной карты: соединение в
адресе, а не в настройках; докачка — отдельный этап (её нет в движке ни для
одного источника); живой стенд — MinIO на `shark`.

**5 октября 2026 — сделано, ждёт живой проверки в приложении.** 36 тестов на
подставке, 4 — движка на `AbortableSink`, 8 живых на MinIO (9 секунд на
полный круг, включая 20 МБ частями с совпадением хеша и отмену многочастной
загрузки без следов).

*Подпись сошлась с опубликованными числами AWS с первого раза* — все пять
векторов. Ошибиться в каноническом запросе незаметно было негде: проверка
не нашими числами.

*Готового MinIO больше нет.* Образа на Docker Hub нет, `quay.io` отказывает,
`dl.min.io` отвечает `410 Gone`: проект ушёл в раздачу исходниками. Стенд
поднят из образа `firstfinger/minio:latest-amd64`, предложенного
пользователем; точки входа в нём нет — сервер запускается командой
`minio server`.

*Живой тест висел — из-за прокси, а не из-за клиента.* `HttpClient` в Dart
молча берёт прокси из окружения: в нём стоял `HTTP_PROXY`, а адреса стенда не
было в строчном `no_proxy` — его Dart и читает первым. Запросы к MinIO в своей
сети уходили в VPN-прокси и не возвращались. Голый `HttpClient` висел так же,
`curl` — нет. Клиент теперь ходит **напрямую**, как `ssh` и `ftp`: иначе
приложение, запущенное из терминала, вело бы себя иначе, чем из Finder.
Урок — в память проекта уже записан (`flutter test` и прокси): он сработал бы,
вспомни я про строчную переменную.

*Разведка сняла с плана целую задачу.* Хешировать части в отдельном изоляте не
пришлось: MinIO принимает тело без хеша и по простому HTTP.
