# Чтение zip: потоком и вне главного изолята

**Состояние:** спецификация к обсуждению. Отметки по ходу — в §9.

Этап [Ж7](../roadmap.md#ж7-чтение-zip-потоком-и-вне-главного-изолята). Открыть
файл из архива сейчас значит распаковать его целиком в память, и сделать это в
том самом изоляте, который рисует окно.

## 1. Что не так — и только у zip

```dart
final bytes = await _readEntry(entry);          // вся запись в памяти
return Stream.fromIterable([...]);              // и кусками наружу
```

Отсюда три беды, и все три видны на большом файле:

* **память в размер записи.** Четырёхгигабайтный файл в архиве не открыть
  вовсе — ни просмотром, ни копированием, ни перетаскиванием наружу;
* **окно встаёт.** Распаковка идёт в главном изоляте: пока она идёт, не рисуется
  ничего, и приложение выглядит зависшим;
* **`canSeek: false`** — честно, но обидно: докачка и чтение с середины
  невозможны, хотя после распаковки данные лежат целиком.

**Это беда одного zip.** `tar` отдаёт `File.openRead(start, end)` — поток и
честный `canSeek`; `7z` тянет содержимое из внешней программы, то есть вообще
из другого процесса. Zip остался единственным, кто распаковывает сам, — потому
что распаковывает он сам.

## 2. Что предлагается

**Распаковывать в файл и в отдельном изоляте, а наружу отдавать поток файла.**

```
openRead → [изолят] распаковать запись в файл во временном каталоге
         → File(...).openRead(offset)
```

Три беды закрываются разом: память ровная (декодер пишет потоком), окно живёт
(главный изолят свободен), `canSeek` становится правдой — распакованное лежит
файлом, и читать его можно с любого места.

**Изолят живёт вместе с провайдером, а не с чтением.** Zip читает оглавление с
конца файла, и открывать архив заново на каждую запись мы уже пробовали: это те
самые 2.7 мс на запись, из-за которых распаковка 2000 файлов занимала 5.4 с
вместо 0.75 с (`providers.md`, 5.6). Значит в изоляте архив держится открытым
столько же, сколько в провайдере, и запросы к нему идут по одному — «распакуй
запись N в файл X».

## 3. Чем платим

**Лишним проходом по диску там, где раньше его не было.** Копирование из архива
на диск сейчас идёт «распаковал в память → записал в цель»; станет «распаковал в
файл → скопировал в цель». Для четырёх гигабайт это лишние четыре гигабайта
записи.

Взамен четыре гигабайта перестают требовать четырёх гигабайт памяти — то есть
работать начинает то, что сейчас не работает вовсе. Обмен честный, но назвать
его надо.

Второй путь, который этого не платит, — §7.

## 4. Что делать с распакованным

Файл во временном каталоге кто-то должен убрать, и вопрос «когда» решается не
сам собой:

| Правило | Чем хорошо | Чем плохо |
|---|---|---|
| убирать по концу чтения | мусора нет вовсе | повторное чтение той же записи распаковывает заново |
| держать всё до `dispose` | быстро всё | копирование 2000 файлов оставит на диске второй архив |
| **держать последнюю запись** | просмотрщик перечитывает даром | одна лишняя запись на диске |

Предлагается третье: **кэш на одну запись**. Просмотрщик читает один и тот же
файл по нескольку раз (поиск, перерисовка, «показать как текст»), а массовое
копирование идёт по разным записям и кэш ему не нужен вовсе.

## 5. Пароль и ошибки

Пароль уходит в изолят вместе с запросом — это строка, и ничем не отличается от
имени записи. Неподошедший пароль возвращается той же ошибкой, что и сейчас, и
спрашивается там же, где спрашивался: в главном изоляте, у человека.

Испорченный архив (`Filter error`) остаётся ошибкой чтения — но теперь она
приходит из изолята, и её надо перевести обратно в `FsError`, не потеряв
причины.

## 6. Отмена

Отмена посреди распаковки — новое умение, которого сейчас нет: сейчас работа
просто стоит, пока запись не распакуется целиком. Изолят даёт возможность
бросить: провайдер закрывает поток, изолят видит, что писать больше некому, и
прекращает. Недописанный файл убирается.

## 7. Чего в первой версии нет

* **Потока прямо из изолята**, без файла посередине. Это и есть способ не
  платить лишним проходом (§3): куски идут через порт по запросу читателя.
  Дороже в устройстве — нужен обратный ход («дай ещё»), иначе быстрый изолят
  завалит медленного читателя, — и его стоит делать, когда станет видно, что
  диск и правда мешает.
* **Общего пула изолятов.** Один изолят на провайдер: архивов открыто обычно
  один-два, а пул решает задачу, которой пока нет.
* **Правки `tar` и `7z`** — им это не нужно (§1).

## 8. Проверка

* большой файл в архиве открывается просмотром, копируется и тащится наружу —
  память при этом ровная;
* окно не встаёт: полоса работы движется всё время распаковки;
* чтение с середины (`offset`) отдаёт то, что и должно, — и `canSeek` больше не
  лжёт;
* повторное чтение той же записи не распаковывает её заново;
* массовое копирование не оставляет на диске второй архив;
* зашифрованная запись спрашивает пароль там же и так же, как раньше;
* испорченный архив говорит об ошибке, а не молчит;
* отмена посреди распаковки прекращает её, и временный файл не остаётся.
