# Ссылка переносится ссылкой, а не вопросом

**Состояние:** спецификация, кода нет. Отметки по ходу работы — в §8.

Копирование `ssh://host/etc/nginx` на диск упирается в вопрос «эту ссылку
сохранить ссылкой здесь нечем» на каждом симлинке — а `sites-enabled` в
`/etc/nginx` только из них и состоит. `mc` то же дерево копирует молча и
правильно. Здесь описано, почему у нас так и что для этого нужно.

## 1. Что происходит

`_resolveLink` (`transfer_engine.dart`) на ссылке, которую не велено разыменовывать:

```dart
if (source != null && identical(source, target) && await source.copyEntry(node, destination, name)) {
  // ссылка ушла ссылкой — но только внутри одного провайдера
}
await _askAboutLink(op, node, links);   // и всё: спросили и пропустили
```

Условие `identical(source, target)` — вот и вся причина. Ссылку умеет создать
только тот провайдер, у которого её и взяли: `copyEntry` — это «сделай копию
**у себя**». Между источником и приёмником у нас нет способа сказать «заведи
ссылку вот на это».

Байтового представления у ссылки нет, потоком её не передать — движок и не
пытается, он спрашивает. Вопрос честный, но ответ на него всегда один и тот же,
и человек отвечает его сотню раз подряд.

## 2. Чего не хватает

Одного примитива у приёмника: **создай ссылку с такой строкой**.

```dart
/// Заводит символическую ссылку [reference] под именем [name].
///
/// false — провайдер ссылок не делает (архив, диск без них, права не те).
Future<bool> createLink(DirectoryNode parent, String name, String reference);
```

Строка, на которую ссылка указывает, у нас уже есть: `LinkNode.reference` —
ровно то, что вернула файловая система, и оба провайдера её заполняют
(`sftp_mapping.dart:20`, `local_tree_provider.dart:97`).

Умеют почти все:

| Провайдер | Чем |
|---|---|
| локальная ФС | `Link(path).create(reference)` — уже делается внутри `copyEntry` |
| SFTP | `SftpClient.link()` — в `dartssh2` есть |
| zip, 7z | нет: ссылка в архиве — это запись со своим видом, и заводят её сами архиваторы |
| память (тесты) | запись типа «ссылка» |

## 3. Что делает движок

```dart
if (!links.follow) {
  if (await _storeLink(source, target, node, destination, name)) {
    return null;                 // ссылка ушла ссылкой
  }
  await _askAboutLink(op, node, links);   // никто не смог — тогда спрашиваем
  return null;
}
```

`_storeLink` пробует по порядку: свой провайдер (`copyEntry`, как сейчас), затем
`createLink` у приёмника. Вопрос остаётся ровно для того случая, ради которого
он и заводился: сохранить ссылку **нечем** — например, кладут в архив.

## 4. Решения

**Строка переносится как есть.** Относительная остаётся относительной,
абсолютная — абсолютной. Так делает `mc`, и это единственное, что можно сделать
честно: ссылка `../sites-available/default` внутри скопированного дерева
продолжит работать, а `/etc/nginx/x` будет указывать туда же, куда указывала. Мы
не знаем, что человек имел в виду, и догадываться, переписывая цель, — хуже, чем
не трогать.

**Битая ссылка — тоже ссылка.** Цели может не быть на той стороне вовсе, и это
не ошибка: `mc` заводит и такие, и `ln -s` тоже. Проверять цель мы не будем.

**Размер ссылки в счёт не идёт.** Как и сейчас: у ссылки нет байтов задания, она
считается одним объектом.

**Права и владелец не переносятся** — это отдельная работа
([Е2](../roadmap.md#е2-правка-атрибутов)), и ссылок она коснётся вместе со всем
остальным.

**Отказ — это `false`, а не исключение.** Провайдер, который ссылок не делает,
отвечает «нет», и движок идёт спрашивать. Windows, где симлинк требует прав,
попадает сюда же: не вышло — значит вопрос, а не падение.

## 5. Чего это не меняет

* **Разыменование (`followLinks`)** — как было: велели идти по ссылке, идём и
  копируем то, куда она ведёт.
* **Вопрос про петлю** (`dir/sub/link → dir`) — как было: это про обход, а не
  про хранение.
* **Архивы.** `zip` и `7z` кладут ссылки записями сами, своим кодом; движок им
  для этого не нужен, и `createLink` они не реализуют.

## 7. Проверка

1. Ссылка уходит ссылкой **между разными провайдерами**: скопировали — на
   приёмнике ссылка с той же строкой, а не файл и не пропуск.
2. Относительная остаётся относительной, абсолютная — абсолютной.
3. Битая ссылка переносится и остаётся битой.
4. Приёмник, который ссылок не умеет, по-прежнему вызывает вопрос — и один на
   всё дерево, если ответили «пропустить все».
5. `followLinks: true` не задет: по ссылке идут и копируют цель.
6. Живьём — то самое `/etc/nginx` с сервера на диск: без вопросов, `ls -l`
   показывает те же ссылки.
