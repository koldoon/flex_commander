# Реестр строк и локализация

**Состояние:** сделано. Отметки по ходу — в §15.

Этап Б1. Интерфейс говорит по-русски и по-английски; язык берётся у системы и
дальше живёт в настройках. Свои строки модуль приносит сам — как приносит
команды, темы и колонки.

## 1. Что не так сейчас

Английский текст написан там, где показывается: подпись команды — в её классе,
заголовок окна — в виджете, объяснение настройки — в схеме. Другого языка не
предусмотрено вовсе, и добавить его нечем: нет ни места, куда положить перевод,
ни того, кто его спросит.

Это не упущение, а порядок работ: локализация стоит после части А потому, что
каждая следующая часть добавляет строки, и чем позже завести реестр, тем больше
придётся переписывать. Строк в приложении около шестисот.

## 2. Что получается

Всё, что человек читает на экране, приходит из реестра: подписи команд и кнопок,
заголовки окон, объяснения настроек, сообщения об ошибках, вехи работы в строке
состояния. Языка два — английский и русский; язык меняется в настройках и
применяется **без перезапуска**.

Модуль объявляет свои переводы там же, где объявляет всё остальное. Выключенный
модуль уносит их с собой, и это ничего не ломает.

## 3. Ключ — сама английская строка

Главное решение этапа, из которого следует почти всё остальное.

```dart
Text(strings.tr('Nothing found'))
```

Не `tr('fc.search.empty')`, а `tr('Nothing found')`. Английский текст **остаётся
на месте** — там, где его читают вместе с кодом, — и он же служит ключом
перевода и запасным значением.

**Почему не идентификаторы** (роадмап предлагал `fc.navigation.up.label`):

* шестьсот идентификаторов надо придумать, и каждый — это ещё один способ
  ошибиться; ключ, выведенный из текста, придумывать не нужно;
* при идентификаторах английский уезжает в словарь, и место показа перестаёт
  быть читаемым: `tr('fc.file.copy.confirm')` не говорит ни о чём;
* **английских словарей не нужно вовсе** — язык по умолчанию уже написан в коде.
  Переводится ровно один словарь, русский;
* перенос идёт по одному литералу и **не меняет поведения**: пока русского
  перевода нет, `tr` возвращает то же, что стояло раньше. Значит, переносить
  можно частями и в любом порядке, а не одним обвалом.

**Чем платим.** Правка английского текста молча роняет перевод в запасной. За
этим следит доктринальный тест (§13): он обходит исходники и требует русский
перевод для каждого ключа. Дешевле, чем шестьсот придуманных имён.

**Одинаковый текст, разный перевод** разводится оговоркой:

```dart
strings.tr('Open', context: 'viewer')   // ключ 'viewer|Open'
```

Ключ с оговоркой ищется только целиком: если перевода нет, берётся английский
текст, а **не** перевод строки без оговорки. Иначе оговорка не разводила бы, а
скрывала.

## 4. Контракт

`fc_api`, `src/l10n/strings.dart` — то есть по обе стороны границы (§5).

```dart
abstract interface class Strings implements Listenable {
  /// 'en' или 'ru'.
  String get language;

  /// Перевод строки. Подстановки — по имени: 'Copy «{name}»'.
  String tr(String text, {Map<String, Object?> args, String? context});

  /// Множественное число: 3 файла, 5 файлов.
  String plural(int count, {required String one, required String other,
                            Map<String, Object?> args, String? context});
}
```

Объявление — в `install` модуля, обеих его половин:

```dart
registry.strings('ru', {
  'Up': 'Наверх',
  'Copy «{name}»': 'Копировать «{name}»',
  'viewer|Open': 'Открыть',
});
registry.plurals('ru', {
  '{n} files': (one: '{n} файл', few: '{n} файла', many: '{n} файлов'),
});
```

**Пространство одно на приложение, а не на модуль.** Модуль — это тот, кто
перевод принёс, а не отдельный словарь: `Cancel` во всех окнах переводится
одинаково, и заводить двадцать словарей ради двадцати одинаковых записей
незачем. Два разных перевода одного ключа — ошибка сборки, а не тихая победа
последнего: реестр на этом падает, и это ровно тот случай, ради которого есть
`context`.

**Подстановки только по имени** (`{name}`), а не по порядку: в переводе слова
меняются местами, а `{name}` переживает перестановку.

**Ключ — литерал без интерполяции.** `tr('Copy $name')` невозможно перевести:
ключ у каждого запуска свой. Такое ловит тот же доктринальный тест.

## 5. Обе стороны, а не только экран

Строку состояния панели пишет **ядро**: `Loading…`, `Reading a.zip…`,
`Connecting to ssh://…` — формулирует тот, кто работает
(`client-server.md`, §6). Значит, реестр нужен и там: контракт живёт в `fc_api`,
который видят обе стороны, а собирается он на каждой стороне из объявлений её
половины модуля (`FrontendRegistry.strings`, `BackendRegistry.strings`).

Через границу строки не ездят и переводиться там не начинают: уезжает готовый
текст, как уезжал.

## 6. Команды

`label` и `description` остаются обычными геттерами — меняется только то, что в
них написано:

```dart
@override
String get label => tr('Copy');

@override
String get description => tr('Copy the selected files to the other panel');
```

`tr` — метод самого `AppCommand`: он спрашивает `appOrNull?.strings`, а команда,
созданная в обход сборки (так делают тесты), получает английский текст. Ни
конструкторы, ни фабрики трогать не приходится — приложение у команды уже есть.

**Название переводится при каждом обращении**, а не один раз при установке: язык
меняется на лету, а ряд кнопок и палитра спрашивают подпись на каждый кадр.

## 7. Ошибки дерева

`FsError` — значение, у него нет служб, и переводить себя ему нечем. Английский
текст `message` остаётся как есть — он уходит в журнал, — а показывают ошибку
через реестр:

```dart
strings.describe(error);   // 'Не найдено: /home/a.txt'
```

Внутри — тот же `switch` по `FsErrorKind`, что и в `message`, но через `tr` с
подстановкой `{path}`. Место одно, и им пользуются обе стороны.

## 8. Множественное число

Английский называет обе формы на месте, русский — три в словаре:

```dart
strings.plural(count, one: '{n} file', other: '{n} files');
```

`{n}` подставляется сам. Ключ русского словаря — форма `other`.

Правило русских форм известно и не меняется:
`n % 10 == 1 && n % 100 != 11` — `one`; `n % 10` в 2…4 и `n % 100` вне 12…14 —
`few`; иначе — `many`. Это чистая функция и проверяется unit-тестом на границах
(1, 2, 5, 11, 21, 111, 0).

Ради двух языков городить CLDR незачем: правил ровно два, и оба написаны здесь.

## 9. Язык

Настройка `language` в разделе оболочки (`fc.shell`), рядом с остальным, чем не
заведует модуль: `system` (умолчание), `en`, `ru`.

**`system` разрешается на каждой стороне самостоятельно** — по
`Platform.localeName` (`ru_RU.UTF-8` → `ru`). Обе стороны стоят на одной машине
и получают один ответ, поэтому везти разрешённый язык через границу не нужно.
Незнакомый язык системы — английский.

**Раздел, а не поле `AppSettings`**: раздел ездит в обе стороны сам и доходит до
ядра живым — тем же приёмом, что язык, повышение прав и кеш каталогов.

## 10. Смена на лету

`Strings` — `Listenable`, как и `ThemeService`. Корень приложения уже слушает
тему (`lib/app.dart`), и реестр встаёт в тот же `Listenable.merge`: смена языка
перестраивает интерфейс так же, как смена темы.

Отдельного «перезапустите приложение» не будет: строки спрашиваются при
отрисовке и нигде не запоминаются.

## 11. Что не переводится

* **Идентификаторы**: команд, настроек, тем, колонок, модулей. Они в файлах и в
  логах, и меняться от языка не вправе.
* **Пути, имена файлов и содержимое** — чужой текст.
* **Названия оболочек и программ** (`zsh`, `rsync`), схемы (`ssh`, `zip`).
* **Журнал**: сообщения `Logger` остаются английскими — их читает разработчик,
  и переводить их значит мешать поиску по коду. Там же и **отчёт об ошибке**:
  его отправляют разработчику, а не читают сами.
* **Текст исключений платформы** (`posix_openpt`, «Cannot copy the file»):
  служб у этого слоя нет, а приходит он внутрь переведённого сообщения —
  «Оболочка не запустилась: …». Перевести его можно будет тогда же, когда у
  ошибок появится вид (`FsErrorKind`), а не строка.
* **Клавиши**: `Cmd-B`, `F5` — имена, а не слова.
* **Документация и коммиты** — они и так по-русски (`docs/`), а
  правило «интерфейс по-английски» этим этапом и отменяется: теперь интерфейс
  по-английски **в коде**, а на экране — на языке человека.

## 12. Порядок работы

Реестр целиком, потом перенос **по модулю за коммит**: навигация, файловые
операции, терминал, поиск, просмотр и правка, архивы, оболочка с окнами, схемы
настроек. После каждого коммита приложение целое и по-английски выглядит ровно
так же, как выглядело, — тесты это и проверяют.

Порядок внутри модуля один и тот же: обернуть литералы, собрать русский словарь,
прогнать доктринальный тест.

## 13. Проверка

**Unit по реестру:** перевод находится; незнакомый ключ возвращает английский;
оговорка разводит одинаковые тексты; два разных перевода одного ключа — ошибка;
подстановки по имени; множественные формы русского на границах.

**Доктринальный тест по исходникам** (тем же приёмом, что `purity_test.dart` в
`core_api`): обходит `lib/` и `dependency/*/lib/`, находит вызовы `tr` и
`plural`, и требует, чтобы

* у каждого ключа был русский перевод — иначе новая строка тихо осталась бы
  английской;
* ни один ключ не был интерполяцией (`tr('Copy $name')`);
* в русских словарях не осталось ключей, которых в коде больше нет.

**Виджет-тест:** смена языка меняет подписи в ряду кнопок и в палитре команд без
перезапуска; `Cancel` в окне становится «Отмена».

**Тесты идут по-английски.** `testApp` ставит `en` явно: прогон не должен
зависеть от языка машины, на которой его запустили, а сотни проверок ищут по
английскому тексту. Русский проверяется там, где проверяется именно он.

## 14. Чего в этом этапе нет

* **Форматов дат, чисел и размеров** — это Б3: им нужны не языки, а настройки
  вида, и живут они в раскладке колонок.
* **Третьего языка.** Механизм его выдержит, но проверять некому: перевод, за
  который никто не отвечает, хуже честного английского.
* **Правки переводов из приложения.** Словарь — код модуля, а не файл рядом с
  настройками.
* **Письма справа налево**: ни арабского, ни иврита не заявлено, а
  `Directionality` тянет за собой пересмотр всей раскладки.
* **Перевода `docs/`** — они и так на русском.

## 15. Отметки по ходу

**Ключ-строка себя оправдал.** Перенос шёл по одному литералу, ни одна правка
не меняла поведения, и приложение оставалось целым между коммитами. Английских
словарей нет вовсе — переведён один русский, около шестисот записей.

**Не всякая строка приходит вызовом.** Названия модулей, колонок, тем, уровней
сжатия и вариантов ответа на вопрос приходят **значением** — из `FsColumn`,
`FcThemeSpec`, `OperationRequestOption`. Переводит их тот, кто показывает
(`strings.tr(value)`), а объявляет — тот, чьё значение. Из-за этого правило
«лишних переводов не держим» пришлось ослабить: лишним считается перевод,
ключа которого **в коде нет вовсе**, а не тот, у которого не нашлось вызова.

**Доктринальный тест читает исходники, а словарь — значения.** `\n` в коде и
перевод строки в памяти — одна и та же строка, и тесту пришлось снимать
экранирование. Найдено на первом же ключе с переносом строки — в вопросе о
правах администратора.

**Оговорка понадобилась ровно там, где ожидалось.** `Cancel` на кнопке окна —
«Отмена», а одноимённая команда панели — «Прервать». Реестр отказался принять
второй перевод того же ключа, и это был не сбой, а ровно та проверка, ради
которой он на таком спорит.

**Область строк — своя, а не поле приложения.** `MaterialApp` пересобирался при
смене языка, но `home: const AppShell()` — константа, и поддерево не
перестраивалось. Отдельный `InheritedNotifier` (`StringsScope`) над
`MaterialApp` решает это честно: подписываются ровно те виджеты, которые
показывают надписи, и окна в накладке тоже.

**Фабрика провайдера сведений строк у приложения не спросит.** Её зовут во
время сборки `AppController`, когда самого приложения ещё нет: строки берутся у
служб (`context.resolve<Strings>()`), как и всё остальное в фабриках.

**Прогон пришпилен к английскому** — `AppOverrides.language`. Иначе он зависел
бы от языка машины, на которой его запустили, а сотни проверок ищут по
английскому тексту. Русский проверяется там, где проверяется именно он:
`test/app/language_test.dart` поднимает настоящее приложение на `ru` и читает
ряд кнопок, заголовки колонок и палитру.

**`fc_text_kit` — не модуль**, а библиотека поиска по тексту, которую берут
просмотрщик и редактор. Строки её команд объявляют оба — одинаковыми записями:
реестр повтор допускает, а спорит только на **разных** переводах одного ключа.
