# Командный фреймворк уходит из API

**Состояние:** сделана 21.08.2026 (начата в тот же день). Что вышло — §7.
Файл остаётся записью о работе: по нему видно, чем доказывалась ненужность
фреймворка и что решено делать, когда составные команды понадобятся.

`dependency/api/lib/src/commands/framework/` — порт
[Spicelib-Commands](https://github.com/spicefactory/Spicelib-Commands) на Dart:
составные команды, обёртки со сроками, данные между шагами, окружение запуска.
Здесь описано, почему он уходит и что встаёт на его место.

История — `docs/refactoring/api-first.md`, фаза Ф2. Тот документ не правится: это
запись о прошлом заходе, а не описание сегодняшнего кода.

## 1. Что там есть

| Файл | Что даёт |
|---|---|
| `command.dart` | `Command`, `ResultCommand`, `CancellableCommand`, `SuspendableCommand`, `CommandFailure`, `CommandResult`, `CommandCanceled`, `CommandTimeout` |
| `command_data.dart` | значения между шагами, поиск по типу |
| `command_executor.dart` | основа составных команд: запуск, отмена, сроки |
| `command_group.dart` | последовательность и параллель |
| `command_proxy.dart` | обёртка над одной командой: срок, обработчики |
| `command_lifecycle.dart` | окружение: чем создать команду, что до и после |
| `commands.dart` | построитель `Commands.asSequence()/inParallel()` |
| `util_commands.dart` | `DelegateCommand`, `DelayCommand` |

1053 строки кода и 593 строки тестов при них.

## 2. Чем доказано, что он не нужен

Грепом по всему дереву. За пределами самого фреймворка и его тестов им
пользуются **два места**:

* `lib/bootstrap/bootstrap.dart` — сборка приложения выражена
  `Commands.asSequence()` из пяти шагов, значения между ними ходят через
  `CommandData`.
* `CommandRegistry` — реализует `CommandLifecycle` и внутри `_runToCompletion`
  заводит `CommandData`/`CommandResult` ради одного вызова.

Ни один модуль (`navigation`, `file_ops`, `zip`, `7z`, `ssh`, `viewer`, `editor`,
`panels`, `default_theme`) фреймворк не импортирует. `SuspendableCommand`,
`CancellableCommand`, `DelegateCommand`, `DelayCommand`, `CommandTimeout` и
`inParallel` не упоминаются вне фреймворка вовсе. `AppCommand implements Command`
берёт оттуда ровно один метод — `execute()`, который объявляет и сам.

Дорожная карта на него тоже не опирается: палитра команд (А4) — это список и
поиск по нему, а «сценарий» в документации значит «команду запустили без окна»,
а не составную команду.

Получается каркас под нагрузку, которой нет, — ровно то, чего сам фреймворк
велел избегать в своём комментарии про непортированный `CommandFlow`: «каркас
под несуществующую нагрузку — это код, который никто не проверяет».

## 3. Что встаёт на его место

**Бутстрап — обычная функция.** Пять шагов статичны и идут строго по порядку;
значения между ними ходят локальными переменными. Поиск по типу
(`CommandData.getObject<T>()`) здесь не давал ничего, кроме возможности
перепутать шаги местами — чего никто не делал.

**Реестр — сам себе окружение.** Три метода `CommandLifecycle` были нужны
фреймворку; реестру они нужны и без него, но как свои: подготовить запуск,
разобрать исход. `_runToCompletion` становится публичным `runToCompletion`, и
им же бутстрап выполняет стартовые команды модулей — с тем же поведением, что
давало `.skipErrors().lifecycle(registry)`: ошибка уходит в `onError`, запуск не
падает.

**`AppCommand` — самостоятельное действие.** `implements Command` уходит,
`execute()` остаётся его собственным методом. Ничего, кроме сигнатуры, там и не
было.

## 4. Чего лишаемся

Честно: составлять команды из команд станет нечем. Когда понадобятся макросы
(«скопировать, потом упаковать, потом удалить») или сценарии, придётся либо
вернуть это из истории git, либо написать заново под настоящую задачу.

Второе вероятнее и лучше. Нынешний порт делался под референс на ActionScript, а
не под то, что просят команды этого приложения: у них есть окна, вопросы по ходу
работы, фоновый режим и `AsyncOperation` со своей отменой и прогрессом — всё то,
чего Spicelib не знал. Составная команда, которую напишут под них, будет другой.

Возврат — один `git revert` коммита удаления: файлы никуда не деваются.

## 6. Проверка

Сам факт удаления проверяется тем, что осталось: 700+ тестов приложения и тесты
каждого модуля должны пройти без единой правки — ни один из них о фреймворке не
знает, и это и есть доказательство.

Отдельно:

* сборка приложения из модулей, чтение настроек до создания приложения, порядок
  шагов — `test/app/bootstrap_test.dart` (уже есть);
* упавший шаг сборки роняет запуск **своей** ошибкой, без обёртки;
* упавшая стартовая команда модуля запуск не роняет (уже есть);
* `flutter analyze` — он же покажет висящие импорты.
